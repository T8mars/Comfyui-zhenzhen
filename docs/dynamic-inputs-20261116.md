# 动态素材接口恢复修复

日期：2026-11-16。基于v2.5.8开发，本组修复纳入v2.5.9发布。仅修改本插件，没有修改ComfyUI_Seedance或其他插件。

## 已确认的问题

不是简单的模型数量定义缺失。当前后端已有G2.6／GPT Image 2.6的16个图片接口和Seedream／Dola 5.5的10个图片接口。[API文档](https://api.seedance.nz/docs/llms.txt)也明确列出平价小屋G2.6静态图最多16张参考图，Seedream 5.5图像编辑1-10张；图层拆分仍是单图输入，不混用编辑上限。

在实际ComfyUI画布中复现：Seedream 5.5连接image1后，image2.hidden已经是false，但原始接口及绘制接口仍保留[-100000,-100000]坐标，最终连接坐标落在画布之外。原始接口与实际绘制接口可能是同一个对象，也可能是副本；直接同步临时隐藏信息会污染后续捕获的原始状态。旧工作流还可能保存了这些临时数据。

另外六组前端组件通过临时替换node.inputs数组计算尺寸；现代ComfyUI的inputs setter可能原地修改插槽集合。这种布局做法会影响接口缓存与连线索引，因此一并移除。

## 修复方式

- 隐藏前先取得干净的坐标与widget描述快照；识别并清理本插件和旧兼容数据的专用隐藏标记，不泛化删除其他widget信息。
- 先捕获全部原始接口，再同步绘制接口，兼容原始／绘制接口共享对象和复制对象两种情况。
- 重新显示时恢复或移除临时坐标、占位widget及绘制状态，不能只改变hidden。
- 真正的控件转输入口描述及自定义坐标保留；已连接接口即便切到不适用模型也不删除，供后端明确校验。
- 保存工作流时使用独立序列化副本，不写入临时隐藏坐标、占位widget或临时绘制属性；不修改原始inputs数组。
- 保留各节点自己的逐路展开规则和真实模型上限，不把所有图片接口常驻，也不统一改成16张。

共享修复位于web/js/dynamic_widget_ui.js，六组布局组件为GPT Image 2.6工坊、G2.6/Krea/Hitem/Meshy、Muse/FLUX/HY、Kling4、NB21/FLUX/Vidu、NB低价/声音克隆。其他调用共享助手的节点自动获得相同的恢复和序列化修复。

## 不止两个节点

“46类节点已覆盖检查”并不表示46类此前都发生了同一种故障。明确复现的Seedream状态恢复问题与六组布局风险采用共享修复；检查范围同时覆盖NB、Qwen、MiniMax、海螺、Wan、Seedance、Omni、FLUX、Muse、HY、Krea、Kling、Vidu、Tripo、Hitem/Meshy/混元3D及声音克隆等相关普通／并发入口。

发布前再次搜索全部前端，补查到Suno、Midjourney、V3.1三个独立的input.hidden赋值路径。它们未调用共享恢复助手，因此先前46类用例未覆盖这三处。现已统一接口与控件的隐藏恢复，不改变各操作、模型原来的适用字段、图片／音频数量或业务参数。G V2及旧NB同文件的静态接口也做兼容检查，不把原本正常的静态接口伪造成已确认故障。

在同一个实际ComfyUI前端，使用v2.5.8的三份旧前端脚本对照：Suno普通生成的非适用音频接口、Midjourney upscale的非适用图片接口、V3.1 lite的非适用图片接口，虽然hidden=true却仍有画布内连接坐标。统一助手后，这些接口真正隐藏；重新切回适用操作或模型时再恢复。三处直接隐藏路径均已纳入回归与静态防回退检查。

没有修改Python运行时、节点注册、输入类型、输出、API请求、并发池、种子参数、工作流控件前缀或现有工作流JSON。用户载入旧工作流时由前端清理残留状态，无需删掉重建节点。

## 验证

所有画布测试使用隔离的本地ComfyUI，前端版本1.58.5。浏览器阻止生成、API和上传POST；未调用付费模型，也不把画布连通测试声称为满数量参考图的上游生成实测。

- 新增恢复单测先在旧实现上失败：显示后的原始坐标仍为-100000；修复后6组共享／复制对象和两种旧标记组合通过，覆盖重复隐藏恢复、绘制接口重建、序列化对象别名、真实转换widget及自定义坐标。
- 第一轮实际画布覆盖46类节点、270组模型／模式／普通／并发组合：检查可见接口的真实坐标、绘制接口标记、命中测试、不重叠、连接扩展、断线、缩放、保存重载和控件值稳定。覆盖图片、视频、音频接口。
- 对FlowMusic九种操作及G2.6、GPT Image 2.6工坊、Seedream 5.5普通／并发入口补测41组重点用例，增加带连线保存重载；与第一轮有重复，不把两轮数字简单相加。
- 发布前补测Suno、Midjourney、V3.1与同文件旧G V2／NB共5类入口、114组模型／操作／普通／并发组合，全部通过，页面错误为零。覆盖操作切换、逐路连接、旧标记清理、断线恢复、缩放和带连线保存重载；不把这部分冒充API生成验证。
- G2.6平价版、GPT Image 2.6工坊、Seedream 5.5及其三个并发版，分别用真实鼠标逐路拖到16、16、10张，共84条独立连接路径。校验image1连接后显示image2，image2连接后显示image3，持续到上限，并检查模型／模式切换、保存重载和提交图中的全部参考输入。
- 对上述六个入口转换提示词和分辨率为外部输入，保存重载后真实widget描述和连线保留；没有把它们误删为隐藏占位信息。
- 31个运行时JavaScript文件和新增测试脚本语法检查通过，557份原有工作流通过JSON、连线、密钥审计，未改写这些工作流。
- 全仓296项Python测试仍为278通过、9失败与9错误，与本轮修改前相同。遗留失败涉及旧导入环境、旧模型断言及旧测试冲突标记，本次没有修改这些无关文件。

未添加依赖、未写入APIKEY、未生成配置密钥文件。隔离测试服务在验收结束后关闭，不影响用户原有ComfyUI进程。
